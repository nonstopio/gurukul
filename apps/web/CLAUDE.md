# Working on `apps/web/`

The single React + Vite app. Three areas share it, gated by role claims:
learner (`/`), Kulapati console (`/kulapati`), Vyasa Studio (`/studio`).
Read the root `CLAUDE.md` and `.claude/skills/gurukul-design/SKILL.md` first.

- From M1, data access goes through small typed modules (`src/data/*`) that take the
  Firestore instance as a parameter, so tests can pass the emulator or a fake.
- Query by role or by `getByRole`/`getByLabelText` in tests, not by class name.
- Cloud Functions are called only through `src/api/` (`.claude/rules/api-responses.md`): a service
  calls `callApi`, screens branch on `error.code` and show `userMessageOf(e, 'fallback')`, never raw
  error text. ESLint rejects `httpsCallable` elsewhere.
- Log with `log.<level>('Constant event', { ids })` (`.claude/rules/logging.md`, skill `writing-logs`):
  no `console.*`, no values in the message, no payloads; a `catch` that shows a toast also logs.
- No course-specific code in the player: if a course needs it, it is a block type.
- Progress writes (`LearnerData.completeItem`, `setLastItem`) land in the local cache at once but
  their promise resolves only when the server acknowledges; never `await` one before moving on, or
  the screen hangs offline. Catch the rejection to log and toast.
