learner (`/`), Studio (`/studio`), Team (`/team`, Managers and Admins), Admin console (`/admin`).
Read the root `CLAUDE.md` and `.claude/skills/gurukul-design/SKILL.md` first.

- A list of courses is `listCourses` (or Studio's `listLiveCourses`): it returns course summaries (`CourseListing`, from
  `courseSummaries/`; `.plan/02-data-model.md`), never course objects, so a list has counts (`lessons`, `quizzes`,
  `chapters` as numbers), `image` and `certificate` but no chapters, lessons, Quiz titles or description. Read the one
  course you need with `getCourse` (the course in progress, a failed Quiz's course); never list whole courses to draw a
  list. `listSummaries` in `data/firebase.ts` counts the same query on `courses` and reads the whole courses only when a
  summary is missing. `percentFor`, `countItems` and `courseImageUrl` (`learn/model.ts`) take either shape. A list
  that can reach `SUMMARY_LIMIT` (`data/limits.ts`) shows `CourseLimitNotice`.
- From M1, data access goes through small typed modules (`src/data/*`) that take the
  Firestore instance as a parameter, so tests can pass the emulator or a fake.
- Query by role or by `getByRole`/`getByLabelText` in tests, not by class name.
- Cloud Functions are called only through `src/api/` (`.claude/rules/api-responses.md`): a service
  calls `callApi`, screens branch on `error.code` and show `userMessageOf(e, 'fallback')`, never raw
  error text. ESLint rejects `httpsCallable` elsewhere.
- Desktop Studio sessions are counted with `session_started` (`SessionLauncher`) and `session_saved`
  (`SaveBar`), whose sizes go through `studio/session/events.ts` (`countBand`, `sessionBands`): bands,
  never a course id or text. `session_discarded` is typed for the Discard still to come. Changing
  what the privacy page says is collected bumps `POLICY_VERSION` with it.
- Log with `log.<level>('Constant event', { ids })` (`.claude/rules/logging.md`, skill `writing-logs`):
  no `console.*`, no values in the message, no payloads; a `catch` that shows a toast also logs.
- No course-specific code in the player: if a course needs it, it is a block type.
- Progress writes (`LearnerData.completeItem`, `setLastItem`) land in the local cache at once but
  their promise resolves only when the server acknowledges; never `await` one before moving on, or
  the screen hangs offline. Catch the rejection to log and toast.
